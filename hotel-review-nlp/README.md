# hotel-review-nlp

**End-to-end NLP engineering project: classical ML → pure-PyTorch BiLSTM → LoRA implemented
from scratch → Qwen2.5 QLoRA fine-tuning → unified benchmark → quantized FastAPI serving.**

One business question - *"is this hotel review positive or negative?"* - solved by five model
families under identical data splits and evaluation, with the winning model served behind a
production-style API. Built to demonstrate the full ML-engineering loop, not just a notebook.

## Why this exists

Most portfolios show one notebook. This repo is structured like a real ML engagement:

| Stage | What happens | Where |
|---|---|---|
| Data | 515K Booking.com reviews → unambiguous binary labels → stratified splits | `reviewnlp/data` |
| Baselines | TF-IDF + MultinomialNB / LR-SGD (word & char n-grams) | `reviewnlp/baselines/classical.py` |
| Deep learning | BiLSTM with a hand-written training loop (packing, clipping, early stop) | `reviewnlp/baselines/bilstm.py` |
| Research-to-code | **LoRA paper (Hu et al. 2021) implemented from scratch in pure PyTorch**, verified 1:1 against HF PEFT | `reviewnlp/lora/lora.py` |
| LLM fine-tuning | Qwen2.5-0.5B-Instruct + QLoRA (NF4, completion-only loss) on a free Colab T4 | `reviewnlp/llm/train_qlora.py` |
| Evaluation | unified benchmark: same test set, McNemar significance tests, latency | `reviewnlp/evaluation/benchmark.py` |
| Serving | FastAPI + Docker, dynamic INT8 quantization benchmark, locust load test | `reviewnlp/serving`, `scripts/` |

## Quickstart

```bash
git clone https://github.com/<your-user>/hotel-review-nlp
cd hotel-review-nlp
make install          # -e .[dev,serving]; add [llm] on a GPU machine

# 1) data (needs the Kaggle CSV - see data/raw/README.md)
make data

# 2) baselines (CPU, minutes)
make baselines
make bilstm           # pure-PyTorch BiLSTM

# 3) transformers (GPU recommended; DistilBERT runs on CPU too)
make distilbert
python -m reviewnlp.llm.train_distilbert_lora --config configs/distilbert.yaml  # scratch LoRA
make qlora             # Qwen2.5 QLoRA - or open notebooks/02_train_qlora_colab.ipynb

# 4) unified benchmark + McNemar + plots
make benchmark

# 5) serve
MODEL_TYPE=encoder MODEL_PATH=runs/distilbert uvicorn reviewnlp.serving.app:app
make quantbench        # INT8 dynamic quantization latency benchmark
locust -f scripts/load_test.py --host http://127.0.0.1:8000 --headless -t 30s
```

### Smoke-test without any data or GPU

```bash
make test    # 27 tests, fully offline: LoRA math, label rules, metrics, API contract
```

## How the LoRA paper shows up in the code

`reviewnlp/lora/lora.py` implements, with zero dependencies beyond PyTorch:

- the paper's update rule `h = W0x + (α/r)·B(A(x))` with `A ∈ R^{r×k}`, `B ∈ R^{d×r}`;
- official initialization (`A` ~ kaiming-uniform, `B = 0` ⇒ ΔW = 0 at step 0);
- dropout on the adapter path only;
- `merge()/unmerge()` folding ΔW into W0 for inference parity;
- adapter-only checkpointing (MBs, not GBs);
- regex `target_modules` injection mirroring PEFT semantics.

`tests/test_lora.py` proves each property, including a numerical 1:1 comparison against
`peft.LoraConfig` on a tiny locally-constructed BERT. `train_distilbert_lora.py` then shows
the practical claim: same encoder, ~0.6% of parameters trainable, comparable F1.

## Serving & quantization

- `MODEL_TYPE` / `MODEL_PATH` env config (12-factor): `stub | classical | encoder | qwen_qlora`.
- `/health`, `/predict`, `/predict/batch` with pydantic validation and per-request latency.
- `scripts/quantize_distilbert.py`: dynamic INT8 on all `nn.Linear`, measuring p50/p95
  latency and accuracy delta before/after → `runs/quantization/benchmark.json`.
- `docker/Dockerfile`: CPU-slim image with a healthcheck; weights are mounted, never baked.
- `scripts/load_test.py`: locust profile producing the RPS/latency numbers for this README.
